SECTION 16.7 — LOCAL EVIDENCE CAPTURE GATEKEEPERS
****************************************************************************************************

BUSINESS PURPOSE:
    Confirm that Section 16 persisted exactly the evidence expected for the current completed Module 2
    strategy run.

    Section 16.7 answers:

        "Did evidence capture create the right persistent evidence rows for this current run key,
         and did those rows preserve the campaign registry identifiers needed for validation-summary,
         README, LinkedIn, and comparison traceability?"

SQL PURPOSE:
    1. Read the current run key from tmp_m2_current_run_key.
    2. Read the current registry / story metadata from tmp_m2_current_run_story_params.
    3. Confirm exactly one executive evidence summary row exists for the current run key.
    4. Confirm validation evidence detail row count matches tmp_m2_validation_status_summary.
    5. Confirm exactly one parameter snapshot row exists for the current run key.
    6. Confirm product × score segment evidence row count matches the latest-run product × score
       segment count.
    7. Confirm required executive summary evidence fields are populated.
    8. Confirm required registry-linkage fields are populated across evidence tables.
    9. Confirm registry-linkage fields stored in evidence tables align to tmp_m2_current_run_story_params.
    10. Confirm parameter snapshot JSON payloads and hash are populated.

        scope.

        campaign_registry_required_flag

        run_registry_match_status
        module1_run_id
        module2_run_id

DECLARE
    /***********************************************************************************************
    Current run key record.

    k RECORD;

    rows.

    Evidence completeness diagnostics.
    ***********************************************************************************************/

    v_validation_registry_gap_count BIGINT;
    v_parameter_registry_gap_count BIGINT;
    v_segment_registry_gap_count BIGINT;

    16.7A Load current run key.

        Scope all local evidence gatekeepers to the current latest-run strategy / Module 1 scenario /

    Assumption:
        Section 16.0 already enforced exactly one row in tmp_m2_current_run_key.

    Failure behavior:
        If no current key exists, subsequent counts will not find expected evidence rows and will
        raise clear exceptions.
    -------------------------------------------------------------------------------------------*/
    SELECT *
    INTO k
    FROM tmp_m2_current_run_key
    LIMIT 1;



    /*-------------------------------------------------------------------------------------------
    16.7B Load current run registry / story metadata.

    Purpose:
        Establish the expected campaign registry fields that should now appear in all persistent
        evidence rows.

    Assumption:
        Section 16.0 already enforced exactly one active story row.

    Registry interpretation:
        RUN_REGISTRY_MATCHED means the row was tied to the formal campaign registry.

        Fallback statuses may appear only when campaign_registry_required_flag is FALSE.
    -------------------------------------------------------------------------------------------*/
    SELECT *
    INTO s
    FROM tmp_m2_current_run_story_params
    WHERE active_story_flag IS TRUE
    LIMIT 1;



    /*-------------------------------------------------------------------------------------------
    16.7C Executive evidence summary row-count gatekeeper.

    Expected:
        exactly one row in credit_decisioning_sim.strategy_run_evidence_summary for the current run
        key.

    Why exactly one:
        The executive evidence summary is one-row-per-run-key evidence.

        Multiple rows would create duplicate or conflicting executive stories.
        Zero rows would mean Section 16.6 did not persist the run-level evidence.
    -------------------------------------------------------------------------------------------*/
    SELECT COUNT(*)
    INTO v_summary_count
    FROM credit_decisioning_sim.strategy_run_evidence_summary e
    WHERE e.strategy_set_name = k.strategy_set_name
      AND e.strategy_name = k.strategy_name
      AND e.strategy_version = k.strategy_version
      AND e.module1_scenario_set_name = k.module1_scenario_set_name
      AND e.module1_scenario_name = k.module1_scenario_name
      AND e.population_id = k.population_id;

    IF v_summary_count <> 1 THEN
        RAISE EXCEPTION
            'Module 2 Section 16 failure: expected exactly one executive evidence summary row for current run, found %.',
            v_summary_count;
    END IF;



    /*-------------------------------------------------------------------------------------------
    16.7D Validation evidence detail row-count gatekeeper.

    Expected:
        persistent validation evidence row count should equal tmp_m2_validation_status_summary row
        count for the current run.

    Why exact count:
        Section 16.3 should capture each Section 14 validation summary row.

        A mismatch means validation evidence was either partially captured or overpopulated.
    -------------------------------------------------------------------------------------------*/
    SELECT COUNT(*)
    INTO v_validation_count
    FROM credit_decisioning_sim.strategy_run_validation_evidence e
    WHERE e.strategy_set_name = k.strategy_set_name
      AND e.strategy_name = k.strategy_name
      AND e.strategy_version = k.strategy_version
      AND e.module1_scenario_set_name = k.module1_scenario_set_name
      AND e.module1_scenario_name = k.module1_scenario_name
      AND e.population_id = k.population_id;

    SELECT COUNT(*)
    INTO v_expected_validation_count
    FROM tmp_m2_validation_status_summary;

    IF v_expected_validation_count <= 0 THEN
        RAISE EXCEPTION
            'Module 2 Section 16 failure: tmp_m2_validation_status_summary contains zero rows.';
    END IF;

    IF v_validation_count <> v_expected_validation_count THEN
        RAISE EXCEPTION
            'Module 2 Section 16 failure: validation evidence row count (%) does not match Section 14 validation summary row count (%).',
            v_validation_count,
            v_expected_validation_count;
    END IF;



    /*-------------------------------------------------------------------------------------------
    16.7E Parameter snapshot row-count gatekeeper.

    Expected:
        exactly one row in credit_decisioning_sim.strategy_run_parameter_snapshot for the current run
        key.

    Why exactly one:
        Each current run key should have one snapshot of:
            active strategy parameters,
            product policy parameters,
            and run-story metadata.

    Failure meaning:
        Zero rows means parameter evidence is missing.
        More than one row means the evidence layer contains duplicate parameter snapshots for the
        same run key.
    -------------------------------------------------------------------------------------------*/
    SELECT COUNT(*)
    INTO v_parameter_snapshot_count
    FROM credit_decisioning_sim.strategy_run_parameter_snapshot e
    WHERE e.strategy_set_name = k.strategy_set_name
      AND e.strategy_name = k.strategy_name
      AND e.strategy_version = k.strategy_version
      AND e.module1_scenario_set_name = k.module1_scenario_set_name
      AND e.module1_scenario_name = k.module1_scenario_name
      AND e.population_id = k.population_id;

    IF v_parameter_snapshot_count <> 1 THEN
        RAISE EXCEPTION
            'Module 2 Section 16 failure: expected exactly one parameter snapshot row for current run, found %.',
            v_parameter_snapshot_count;
    END IF;



    /*-------------------------------------------------------------------------------------------
    16.7F Segment evidence row-count gatekeeper.

    Expected:
        Persistent segment evidence row count should equal the number of distinct product × score
        combinations in the current latest-run output.

    Why this matters:
        Section 16.5 is the product × score companion evidence layer.

        If it misses a segment, executive driver fields may not be supported by complete drill-down
        evidence.

        If it overpopulates segments, the evidence layer may be mixing current-run and stale segment
        rows.
    -------------------------------------------------------------------------------------------*/

    INTO v_segment_count
    FROM credit_decisioning_sim.strategy_run_segment_evidence_summary e

      AND e.strategy_name = k.strategy_name
      AND e.strategy_version = k.strategy_version
      AND e.module1_scenario_set_name = k.module1_scenario_set_name
      AND e.module1_scenario_name = k.module1_scenario_name
      AND e.population_id = k.population_id;

    SELECT COUNT(*)
    INTO v_expected_segment_count
    FROM (
        SELECT DISTINCT
            product_type_policy_key,
            score_band_policy_key
        FROM credit_decisioning_sim.strategy_decisions
    ) d;

    IF v_segment_count <> v_expected_segment_count THEN
        RAISE EXCEPTION
            'Module 2 Section 16 failure: segment evidence row count (%) does not match expected product × score segment count (%).',
            v_segment_count,
            v_expected_segment_count;
    END IF;



    /*-------------------------------------------------------------------------------------------
    16.7G Executive evidence required-field completeness gatekeeper.

    Expected:
        Required executive evidence fields should be populated.

    Required field families:
        evidence capture metadata,
        registry linkage,
        strategy identity,
        Module 1 lineage,
        application count,
        decision rates,
        simulated offer-exposure rate,
        approved amount,
        approved Expected Loss,
        top primary simulated reason code,
        validation status counts,
        and Module 3 boundary fields.

    SELECT COUNT(*)
    INTO v_null_required_summary_count
    FROM credit_decisioning_sim.strategy_run_evidence_summary e
    WHERE e.strategy_set_name = k.strategy_set_name
      AND e.strategy_name = k.strategy_name
      AND e.strategy_version = k.strategy_version
      AND e.module1_scenario_set_name = k.module1_scenario_set_name
      AND e.module1_scenario_name = k.module1_scenario_name
      AND e.population_id = k.population_id
      AND (
             e.evidence_snapshot_ts IS NULL

          OR e.campaign_registry_required_flag IS NULL
          OR e.registry_match_count IS NULL
          OR e.run_registry_match_status IS NULL
          OR e.module1_run_id IS NULL
          OR e.module2_run_id IS NULL
          OR e.showcase_name IS NULL

          OR (
                e.campaign_registry_required_flag IS TRUE
            AND (
                    e.run_registry_match_status <> 'RUN_REGISTRY_MATCHED'
                 OR e.run_sequence_number IS NULL
                 OR e.showcase_id IS NULL
                 OR e.validation_evidence_group_id IS NULL
                )
             )

          OR e.strategy_set_name IS NULL
          OR e.strategy_name IS NULL
          OR e.strategy_version IS NULL
          OR e.module1_scenario_set_name IS NULL
          OR e.module1_scenario_name IS NULL
          OR e.population_id IS NULL

          OR e.applications IS NULL
          OR e.approval_rate IS NULL
          OR e.counteroffer_rate IS NULL
          OR e.manual_review_rate IS NULL
          OR e.decline_rate IS NULL
          OR e.simulated_offer_exposure_rate IS NULL

          OR e.total_approved_amount IS NULL
          OR e.total_approved_expected_loss_amount IS NULL
          OR e.top_primary_reason_code IS NULL

          OR e.validation_pass_count IS NULL
          OR e.validation_review_count IS NULL
          OR e.validation_not_applicable_count IS NULL
          OR e.validation_status_summary_jsonb IS NULL

          OR e.module3_revenue_model_required_flag IS NULL
          OR e.module3_boundary_note IS NULL
      );

    IF v_null_required_summary_count > 0 THEN
        RAISE EXCEPTION
            'Module 2 Section 16 failure: executive evidence summary has null or invalid required evidence fields.';
    END IF;



    /*-------------------------------------------------------------------------------------------
    16.7H Registry-linkage completeness gatekeeper for validation evidence.

    Expected:
        Every persisted validation evidence row for the current run should carry the run ID and

    SELECT COUNT(*)
    INTO v_validation_registry_gap_count
    FROM credit_decisioning_sim.strategy_run_validation_evidence e
    WHERE e.strategy_set_name = k.strategy_set_name
      AND e.strategy_name = k.strategy_name
      AND e.strategy_version = k.strategy_version
      AND e.module1_scenario_set_name = k.module1_scenario_set_name
      AND e.module1_scenario_name = k.module1_scenario_name
      AND e.population_id = k.population_id

             e.campaign_registry_required_flag IS NULL
          OR e.registry_match_count IS NULL
          OR e.run_registry_match_status IS NULL
          OR e.module1_run_id IS NULL

             )

            'Module 2 Section 16 failure: % validation evidence row(s) are missing required registry-linkage fields.',
            v_validation_registry_gap_count;
    END IF;



    /*-------------------------------------------------------------------------------------------
    16.7I Registry-linkage completeness gatekeeper for parameter snapshot.

    Expected:
        The parameter snapshot row should carry the run ID, registry match status, and documentation

    SELECT COUNT(*)
    INTO v_parameter_registry_gap_count
    FROM credit_decisioning_sim.strategy_run_parameter_snapshot e

      AND e.strategy_name = k.strategy_name

      AND e.module1_scenario_set_name = k.module1_scenario_set_name
      AND e.module1_scenario_name = k.module1_scenario_name
      AND e.population_id = k.population_id
      AND (
             e.campaign_registry_required_flag IS NULL
          OR e.registry_match_count IS NULL
          OR e.run_registry_match_status IS NULL
          OR e.module1_run_id IS NULL
          OR e.module2_run_id IS NULL
          OR e.showcase_name IS NULL
          OR (
                e.campaign_registry_required_flag IS TRUE
            AND (
                    e.run_registry_match_status <> 'RUN_REGISTRY_MATCHED'

                 OR e.showcase_id IS NULL
                 OR e.validation_evidence_group_id IS NULL
                )
             )

        Every product × score segment evidence row should carry the same registry linkage used by the

             e.campaign_registry_required_flag IS NULL

          OR e.run_registry_match_status IS NULL

          OR (

            AND (
                    e.run_registry_match_status <> 'RUN_REGISTRY_MATCHED'

                 OR e.validation_evidence_group_id IS NULL

    /*-------------------------------------------------------------------------------------------

    INTO v_registry_alignment_violation_count
    FROM (
        SELECT 1
        FROM credit_decisioning_sim.strategy_run_evidence_summary e

          AND e.strategy_name = k.strategy_name
          AND e.strategy_version = k.strategy_version
          AND e.module1_scenario_set_name = k.module1_scenario_set_name
          AND e.module1_scenario_name = k.module1_scenario_name
          AND e.population_id = k.population_id
          AND (
                 e.campaign_registry_required_flag IS DISTINCT FROM s.campaign_registry_required_flag
              OR e.registry_match_count IS DISTINCT FROM s.registry_match_count
              OR e.run_registry_match_status IS DISTINCT FROM s.run_registry_match_status
              OR e.module1_run_id IS DISTINCT FROM s.module1_run_id
              OR e.module2_run_id IS DISTINCT FROM s.module2_run_id
              OR e.run_sequence_number IS DISTINCT FROM s.run_sequence_number
              OR e.showcase_id IS DISTINCT FROM s.showcase_id
              OR e.showcase_name IS DISTINCT FROM s.showcase_name
              OR e.comparison_group_id IS DISTINCT FROM s.comparison_group_id
              OR e.validation_evidence_group_id IS DISTINCT FROM s.validation_evidence_group_id
              OR e.readme_storyline_label IS DISTINCT FROM s.readme_storyline_label
              OR e.linkedin_post_sequence IS DISTINCT FROM s.linkedin_post_sequence
              OR e.validation_summary_section_hint IS DISTINCT FROM s.validation_summary_section_hint
          )

        UNION ALL

        SELECT 1
        FROM credit_decisioning_sim.strategy_run_validation_evidence e
        WHERE e.strategy_set_name = k.strategy_set_name
          AND e.strategy_name = k.strategy_name
          AND e.strategy_version = k.strategy_version
          AND e.module1_scenario_set_name = k.module1_scenario_set_name
          AND e.module1_scenario_name = k.module1_scenario_name
          AND e.population_id = k.population_id
          AND (
                 e.campaign_registry_required_flag IS DISTINCT FROM s.campaign_registry_required_flag
              OR e.registry_match_count IS DISTINCT FROM s.registry_match_count
              OR e.run_registry_match_status IS DISTINCT FROM s.run_registry_match_status
              OR e.module1_run_id IS DISTINCT FROM s.module1_run_id
              OR e.module2_run_id IS DISTINCT FROM s.module2_run_id
              OR e.run_sequence_number IS DISTINCT FROM s.run_sequence_number
              OR e.showcase_id IS DISTINCT FROM s.showcase_id
              OR e.showcase_name IS DISTINCT FROM s.showcase_name
              OR e.comparison_group_id IS DISTINCT FROM s.comparison_group_id
              OR e.validation_evidence_group_id IS DISTINCT FROM s.validation_evidence_group_id
              OR e.readme_storyline_label IS DISTINCT FROM s.readme_storyline_label
              OR e.linkedin_post_sequence IS DISTINCT FROM s.linkedin_post_sequence
              OR e.validation_summary_section_hint IS DISTINCT FROM s.validation_summary_section_hint
          )

        UNION ALL

        SELECT 1
        FROM credit_decisioning_sim.strategy_run_parameter_snapshot e
        WHERE e.strategy_set_name = k.strategy_set_name
